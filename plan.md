### Goal
The live-comparison.js script successfully decrypts Chrome's token but fails to decrypt the standalone token for field-by-field comparison (logs "Cannot compare fields — one or both decryptions failed"). Fix the standalone token decryption so we can see exactly how many fields differ.

### Context
- `scripts/live-comparison.js` line 478: `decryptCollect(standaloneCollect, xteaParams)` returns null parsed
- The standalone collect token is generated by `generateCollect()` which URL-encodes the result
- `decryptCollect()` URL-decodes, base64-decodes, then XTEA-decrypts as one block
- Chrome's token decrypts fine with the same function — so the issue is likely in the standalone token format
- Possible cause: `generateCollect()` may double-encode or use different encoding conventions

   - Check if generateCollect returns already-decoded or still URL-encoded
   - Try decrypting without URL-decode step
2. Fix the comparison so both tokens can be decrypted and compared field-by-field
3. Run live again to verify comparison works
